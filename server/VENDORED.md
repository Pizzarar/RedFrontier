Not vendored on purpose (skipped from the recipe for the B1 minimum): rsg-hud, rsg-banking, rsg-wardrobe, rsg-menubase, PolyZone, menu_base, rNotify, rsg-voice, xsound, etc.
Local edit (B-access): `rsg-core/shared/config.lua` sets `RSGConfig.Server.Whitelist = true` and `WhitelistPermission = 'fh.allowlist'` (was `false` / `'admin'`); see fh_core README "Access".
Local edit (B-access): `rsg-core/locales/en.json` `error.not_whitelisted` now reads "You're not on this private server's allowlist. Ask the owner to add you: they can see your ID in the server console." (was "[RSGCORE] - You're not whitelisted for this server"); it is the only reject message a non-allowlisted player sees (JSON has no comments, so it is recorded here).
Local edit (core M2, money items always survive): `rsg-core/server/moneyitems.lua` no longer listens on `RSGCore:Server:OnMoneyChange`; it exposes `ApplyMoneyItems(player, moneytype, amount, op)`, whose add / remove / set are all-or-nothing (adds first, a failed add undone by removing the adds already done; set = add/remove of the difference; the item value is checked before and after). `rsg-core/server/player.lua` AddMoney / RemoveMoney / SetMoney call it before reporting success and return false with the balance put back when the items could not move (full inventory, over weight, no room for change). Upstream returned true while the money-item sync dropped the cash. Spec: `spec/money_items_fit_spec.lua`.
Local edit (core M2-nit): `rsg-core/server/moneyitems.lua` `removeItems` takes the whole amount in one slotless `RemoveItem` (upstream / M2 removed per slot, so fh_inventory's ConvertCoins could merge >=100 split cents into a dollar between removals and the first slot's cents were lost on the false return); a refused step in `applyMoves` undoes the adds and gives the removed items back. While `ApplyMoneyItems` runs, `SynchronizeMoneyItems` leaves the balance alone, so the HUD gets one `hud:client:OnMoneyChange` per AddMoney / RemoveMoney / SetMoney instead of one per item step, and the sync only sends HUD changes of at least a cent (no float-residue events). Spec: `spec/money_items_fit_spec.lua`.
Local edits (core P1, weapon/ammo use): rsg-ammo is vendored byte-for-byte; rsg-weapons has the P5 local edit below. Their only deps are rsg-core, rsg-inventory (fh_inventory `provide`s it) and oxmysql (rsg-ammo), all present, so no GetResourceState guards were needed. rsg-weapons' throwable path checks `GetResourceState('rsg-ammo') == 'started'` itself. rsg-ammo (not in the task text) was added because rsg-weapons has no ammo-box handler: upstream splits it out, and it also saves ammo per character in `player_ammo` (table is in 0001_rsg_schema.sql, rsg-ammo adds missing columns itself).
Local edit (core-08 P5, rsg-weapons): `rsg-weapons/config.lua` sets `Config.WeaponComponents = false` (was `true`) because `rsg-weaponcomp` is not vendored, disabling the `rsg-weaponcomp:server:removeComponents` / `check_comps` triggers in `rsg-weapons/client/client.lua`.
Local edit (core-08 P2, no dead use buttons): `rsg-core/shared/items.lua` sets `useable = false` on 20 loot items that no resource gives a use handler: bandana, bucket, canned_peaches, chewingtobacco, cigar, cigarettes, moonshine, mortarpestle, oilcan, pipe, resource_coal, resource_copper_bar, resource_gold_nugget, resource_iron_bar, resource_silver_bar, resource_wood, shovel, tool_goldpan, tool_lockpick, weapon_gun_oil (was `true`; `weapon_repair_kit` stays true: rsg-weapons registers it). fh_inventory now says "You can't use that." for a use press on an item with no handler. Medical/tonic/money-clip items keep `useable = true`: `fh_core/server/useables.lua` handles them. Weapons, ammo boxes and binoculars are P1's (rsg-weapons).
rsg-core guards its optional rsg-banking call with GetResourceState. Add more as later blocks need them.
